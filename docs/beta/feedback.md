# 公测反馈与问题上报

日期：2026-10-14。

教师不直接对着代码仓库排障。学校内部先收到问题，再由运维决定要不要开 GitHub Issue。**【待填写：学校内部联系人、邮箱或即时通讯、期望响应时间】**

**【待作者确认】** 本仓库 Issue 对能阅读仓库的人可见。在作者明确授权之前，不要把教师账号加进仓库，也不要让学生自己开 Issue。

## 1. 教师怎么报

上课时或当天，发给学校联系人，写清这些就够：

1. 您的角色（教师 / 管理员）和班级名称。不要附全班名册。
2. 大约时间（含时区，或写「北京时间」）。
3. 您想做的事，以及屏幕上的原文提示。
4. 浏览器名称。能看响应头时，附上 `x-request-id`。没有也可以。
5. 有没有刚启用插件、刚改 AI 配置、或全班同时提交。

下面这些不要出现在邮件、聊天记录或 Issue 里：

- 密码、班级临时口令、Cookie、`edu_os_token`
- AI 的 API Key，以及密钥的前几位后几位
- 学生作业原文、考试题和答案、成绩单导出文件
- 身份证号、家庭住址、电话、健康信息
- `.env`、`ENCRYPTION_KEY`、`storage/bootstrap-credentials.txt` 的内容

需要说明「某位学生提交失败」时，用学号的末几位或「3 班第 2 次作业」，让运维在服务器上查。

学生遇到问题时告诉任课教师，由教师汇总。公测不设学生直达的公开表单。**【待学校确认：是否允许家长联系学校信息中心，渠道是什么】**

## 2. 运维什么时候开 Issue

学校联系人确认这是软件行为，而不是忘了改密、没启用插件或网络中断之后，由运维在本仓库开 Issue。

| 情况 | 用哪张表单 |
| --- | --- |
| 按步骤能再次出现的错误、数据不对、权限不对 | [缺陷报告](../../.github/ISSUE_TEMPLATE/bug_report.yml) |
| 教学上需要、当前版本没有的能力 | [功能建议](../../.github/ISSUE_TEMPLATE/feature_request.yml) |
| 服务器宕机、要恢复备份、密钥配置 | 不要开公开 Issue。按 [运营手册](operations.md) 处理，只在内部值班记录里写 |

表单里每一项的说明和「不要粘贴」的提醒已经写在模板上。仓库若还没有 `bug` 标签，模板不自动加标签，避免开单失败。

严重程度由运维填写，不要求教师判断：

| 级别 | 含义 | 公测期间怎么处理 |
| --- | --- | --- |
| 停课 | 登录、建班或全班提交不可用，或怀疑学生数据被不该看的人看到 | 先按运营手册停写流量或回滚。内部通知联系人。修复前不要在 Issue 里贴数据样本 |
| 出错但能上课 | 单个功能失败，有绕过办法 | 开缺陷报告，带上请求编号 |
| 建议 | 不影响当前课 | 开功能建议。不承诺进公测版本 |

**【待作者确认】** 谁看 Issue、几天内回复、停课级问题是否有人值班。公告里的联系方式必须和这里是同一个人或同一个值班表。

## 3. 开单前先对一下已知问题

[已知问题与限制](known-issues.md) 里已经写明的行为，仍然可以开单，标题注明「已知问题仍影响上课」，避免和已修复的审计项重复。

这些情况先在服务器上核对，多半不是新缺陷：

- 改密前访问班级列表得到 403，响应码 `FORBIDDEN_DEFAULT_PASSWORD`
- 插件安装成功但路由是 503，状态仍是 `installed`（还没启用）
- 插件声明了匿名访问，批准前是 401
- 登录或提交收到「过于频繁」
- 恢复备份之后 AI 提供商不可用（`ENCRYPTION_KEY` 与备份时不一致，或密钥显示 `[UNDECRYPTABLE]`）

## 4. 缺陷报告里建议附上的服务器信息

运维从本机查看，不要把日志全文贴进 Issue。

- `/health` 的 `version` 与 `status`
- 对应时间的 `http.request` 一行：`requestId`、`method`、`path`、`status`、`durationMs`。路径不含查询串。确认该行没有口令、Cookie 和学生作答
- 若是登录失败、429、403、插件安装或公开路由批准，在 `audit.log` 里找同名事件：`auth.login_failed`、`rate_limit.triggered`、`auth.forbidden`、`plugin.installed`、`plugin.enabled`、`plugin.public_route_approved`
- 容器是否在重启：`RestartCount`。人为 `docker kill` 不会自动拉起

日志目录默认是进程工作目录下的 `logs/`。compose 设为 `/data/logs`，同时写 stdout。`SENTRY_DSN` 或 `OPENLEARN_ERROR_DSN` 若已配置，错误的副本在那个系统里，Issue 里给事件编号即可。
