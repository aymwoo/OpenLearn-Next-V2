# Roadmap v0.3.0+ — 下一阶段开发目标（修订版 v2）

> 本路线图基于 2026-08-30 对平台（`openlearn-next@0.2.6`）的代码审计与计划自审修正而成。
> 计划自审结论：原计划存在 4 处事实错误（测试数、esm-loader、capability-system 删除建议、`any` 目标）与 6 处遗漏（安全矛盾、迁移僵尸、di-tokens 失效注释、E2E、v2_plugins 失效配置、capability 命名混乱），均已在本版修正。

## 0. 背景：审计关键结论

- 630 个源码文件（96,060 LOC），**167 个测试文件**（前端 `src/` 覆盖良好，后端核心引擎为黑洞）

- 近期 60 次提交：refactor 30 / docs 13 / fix 10 / feat 1 / test 1 —— 重维护、轻功能、测试几乎停摆

## 1. 阶段 A：质量基线（0.3.0–0.3.1，约 6 周）

### A0 — 安全裁决（0.3.0 首周，P0）
**目标**：定案 iframe `allow-same-origin` 矛盾并统一；CSP/审批流回归。
**任务**：
1. 评审 Bridge SDK 的 `Object.defineProperty + Proxy` 方案是否仍依赖 `allow-same-origin`（commit 6d01567 之后）；
2. 若不依赖 → 从全部 iframe sandbox 移除 `allow-same-origin`，恢复严格隔离，更新 AGENTS.md；
3. 若依赖 → 接受现状，更新 AGENTS.md 说明"经 Bridge Proxy 方案，sandbox 含 allow-same-origin 且 postMessage 归一化"，并将安全影响写入手册；
4. 回归 `f1de341` 修复的 P0 项（含 `pending_commands` 审批流）。

**验收**：AGENTS.md 与代码一致；安全手册更新；审批流回归测试通过。

### A1 — 后端核心测试（0.3.0 第 2–4 周，P0）
> 修正：聚焦**后端核心引擎**（前端 `src/` 已有较好覆盖），且拆分可交付粒度。

**A1a（第 2–3 周）— 最危险 4 个**：
- `packages/core/db/`（数据库引导，最核心）
- `packages/core/bootstrap/`（5 阶段启动管线，文档详尽但零测试）
- `packages/core/command-bus/`
- `packages/core/event-bus/`

**A1b（第 4–6 周）— 引擎类 4 个**：
- `packages/core/lesson-engine/`
- `packages/core/analytics-engine/`
- `packages/core/collaboration-engine/`
- `packages/core/presence-engine/`

**A1c（0.3.1，第 7–9 周）— 其余**：`registry`、`service-registry`、`configuration`、`capability`、`capability-governance`、`ai`。

**验收**：A1a 四个目录单测覆盖率 ≥60%；引擎类核心路径（创建→执行→发布事件）有集成测试。

### A2 — 迁移系统裁决（0.3.0 第 2–4 周，P0）
**目标**：要么接通 `runMigrations`，要么删除僵尸。
**推荐**：接通。
1. 将 `packages/core/db/index.ts` 的内联 `CREATE TABLE` 拆为 `migrations/NNN_*.sql`（UP/DOWN 双段，遵循 README 约定）；
2. `server/utils/migrate.ts` 在启动时按序执行并记录 `_migrations`；
3. `server/bootstrap-db.ts` 的 `try/catch ALTER` 逐步迁移进版本化迁移。
**验收**：`migrations/` ≥10 个 `.sql`；启动日志显示迁移执行；`_migrations` 表有记录；`ALTER` 遗留模式清零。

### A3 — 删除死代码（0.3.0 第 1 周，P1）
`extractManifestFromBundle()`：实现它（把 ZIP 提取与 manifest 解析拆开）或从导出中移除。
**验收**：`install-utils.ts` 无 throw-not-implemented 的公开导出。

### A4 — capability 目录梳理（0.3.1，P1）
> 修正：**禁止删除 `capability-system`**（它是活的 `CapabilityGuard` RBAC）。
1. 先绘制 5 个 capability 目录（`capability/`、`capability-runtime/`、`capability-system/`、`ai-capability/`、`capability-governance/`）的依赖图与职责边界；
2. 重命名使其名副其实（如 `capability-system` → `rbac-guard` 或并入 `capability/` 的 guard 模块）；
3. 合并/删除真正冗余者（以依赖图为据）；
4. 收敛文档交叉引用到 1–2 处。
**验收**：目录 ≤3；依赖图入库；文档一致。

### A5 — `any` 收敛（0.3.0 起持续，P2）
> 修正：不可行目标"≤300"改为**渐进收敛**。
1. 为 ESLint 建立 `no-explicit-any` **基线白名单**（现有文件允许，新文件禁止）；
2. worst 5 文件各 -50%（`server/routes/roster.ts` 71、`packages/plugins/builtin.ts` 51、`ClassAssignmentsPanel.tsx` 43、`server/routes/lessons.ts` 36、`server/routes/plugins.ts` 32）；
3. 目标：0.3.x 结束时总量 ≤600，0.4.x 结束时 ≤300。
**验收**：新代码无 `any`（CI 阻断）；worst 5 文件减半。
