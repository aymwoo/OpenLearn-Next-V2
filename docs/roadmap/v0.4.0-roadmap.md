### v0.3.21 审计新发现

本次审计发现 **25 个 P0-P2 问题**，其中：

- **P0（6 个）**：全部为安全/数据完整性问题 — 13+ API 端点无认证、零外键约束、级联删除缺事务、测验提交竞态条件
- **P1（10 个）**：架构瓶颈与可靠性风险 — God 组件恶化、内存泄漏、AI 无超时、无 CSRF 防护

**核心矛盾**：内核架构（CQRS/EventBus/DI/插件系统）设计精良，但**外围安全边界**（路由层认证、数据库约束）和**前端架构**（God 组件、状态管理）成为系统性短板。

## 1. 阶段 S：安全加固（v0.4.0 首周，P0 紧急）

> **目标**：消除全部 P0 安全问题。这是后续所有工作的前提。
> **预估**：1-2 周。

### S1 — API 认证补全（P0，3-5 天）

**问题**：13+ 端点缺少 `requireAuth` 中间件，匿名用户可访问学生数据、提交记录、白板数据，甚至写入磁盘。

**任务**：

| # | 端点 | 修复 | 预估 |
|---|---|---|---|
| S1a | `GET /api/students` | 添加 `requireAuth` + 角色过滤 | 0.5h |
| S1b | `GET /api/assignments/:id/submissions` | 添加 `requireAuth` + 教师/学生权限分离 | 1h |
| S1c | `POST /api/courseware/debug` | **删除此端点**或添加 auth + 输入限制 | 0.5h |
| S1d | `POST /api/upload` | 添加 `requireAuth` | 0.5h |
| S1e | `GET /api/classes`, `GET /api/lessons` | 添加 `requireAuth` | 1h |
| S1f | `GET /api/lessons/:id/whiteboard` | 添加 `requireAuth` + 课时归属验证 | 1h |
| S1g | `POST /api/courseware/attempts/:id/promote` | 添加 `requireAuth` + 教师角色检查 | 0.5h |
| S1h | `GET /api/classes/:classId/attendance-summary` | 添加 `requireAuth` | 0.5h |

| S1j | `GET /api/mfe/remotes` | 添加 `requireAuth` | 0.5h |

**验收**：所有端点 require 认证；编写集成测试验证未认证请求返回 401/403。

### S2 — 硬编码 Admin 提权消除（P0，1 天）

**问题**：`server/middleware/auth.ts:60-67` 和 `packages/core/kernel/index.ts:268-274` 通过用户名/userId 字符串匹配自动提升管理员权限。

**任务**：
1. `auth.ts` — 移除 `username === 'admin'` 和 `userId === 'usr_admin'` 硬编码，改为查询 `users.role` 字段
2. `kernel/index.ts` — 移除 `actorId === 'admin'`、`actorId === 'usr_admin'`、`actorId?.endsWith(':admin')` 等字符串匹配，统一走 CapabilityGuard 角色检查
3. 确保 `packages/plugins/builtin.ts` 中 admin 用户的初始 role 在数据库中正确设置为 `administrator`

**验收**：admin 权限完全由数据库 `users.role` 字段决定；无字符串匹配提权路径；现有 admin/teacher 登录功能正常。

### S3 — Socket.IO 房间鉴权（P0，0.5 天）

**问题**：`server/presence.ts:111-113` 允许任何 Socket 加入任意房间。

**任务**：
1. `join-room` 事件处理器中验证 socket session 关联的学生/教师是否属于该房间对应的课时/班级
2. 拒绝未授权的 join 请求并记录审计日志

**验收**：学生只能加入自己班级的课堂房间；教师可加入自己授课的房间；测试覆盖越权场景。

### S4 — 外键约束引入（P0，2-3 天）

**问题**：整个 Schema 零 `FOREIGN KEY` 约束，引用完整性完全依赖应用层代码。

**任务**：
1. 编写 `migrations/006_add_foreign_keys.sql`，为以下关键关联添加外键：
   - `class_students.class_id → classes.id`
   - `class_students.student_id → students.id`
   - `student_lesson_progress.student_id → students.id`
   - `assignment_submissions.assignment_id → assignments.id`
   - `whiteboard_elements.lesson_id → lessons.id`
   - `attendance.schedule_id → schedules.id`
   - `plugin_submissions.lesson_id → lessons.id`
   - `plugin_grades.submission_id → plugin_submissions.id`
2. 迁移前运行数据一致性检查脚本，清理现有孤儿数据
3. 为 `ON DELETE` 行为选择策略：
   - 级联删除（`CASCADE`）：whiteboard_elements、attendance、student_lesson_progress
   - 限制删除（`RESTRICT`）：classes（有学生时禁止删除）、students（有提交记录时禁止删除）

**验收**：迁移成功执行；尝试插入孤儿数据被数据库拒绝；现有功能不受影响。

**风险**：SQLite 添加外键到已有表需要 `ALTER TABLE` + 重建（SQLite 不支持 `ADD CONSTRAINT`）。需要通过 `CREATE TABLE ... AS SELECT ...` 重建方式迁移。

## 3. 阶段 B：认证与错误处理加固（v0.4.0 第 3-4 周，P1-P2）

> **目标**：统一安全边界和错误处理。
> **预估**：1.5 周。

### B1 — CSRF 防护（P1，2 天）

**问题**：Cookie-only 认证无 CSRF 防护。

**任务**：
1. 评估方案：Double Submit Cookie vs SameSite 属性 vs CSRF Token
2. 推荐：将 session cookie 设置为 `SameSite=Lax`（如果当前不是），并对状态变更端点（POST/PUT/DELETE）添加 CSRF Token 验证
3. 在 `server/middleware/` 新增 `csrf.ts` 中间件

**验收**：跨域 POST 请求被拒绝；同源请求正常通过。

### B2 — 错误处理统一（P2，1 天）

**任务**：
1. 全局搜索 `res.status(500).json({ error:` 替换为 `sendSafeError(res, err)`
2. 移除 `roster.ts` 中非标准状态码 `550`
3. 添加全局 Express 错误处理中间件兜底

**验收**：生产环境下 500 响应不泄露内部错误信息；所有错误响应格式一致。

### B3 — ID 生成安全化（P2，0.5 天）

**任务**：
1. 全局搜索 `Math.random().toString(36)` 替换为 `crypto.randomUUID()` 或 `uuid` 包
2. 涉及文件：`server/routes/admin.ts`, `server/routes/roster.ts`

**验收**：所有新生成的 ID 不可预测。

### B4 — 内存泄漏修复（P1，0.5 天）

**任务**：
1. `server/shared-state.ts` — `MF_REMOTE_CACHE` 添加 LRU 淘汰（max 100 entries）或 TTL（5 分钟）
2. `server/shared-state.ts` — `lessonActiveSegments` 在课时结束/删除时清理条目
3. `packages/core/event-bus/index.ts` — `subscribe()` 返回 `() => void` 取消函数；添加最大监听器警告（>50 同类型）

**验收**：长时间运行测试（1 小时持续请求）内存增长 < 20%。

### B5 — AI Provider 可靠性（P1，1 天）

**任务**：
1. `server/ai-agent.ts` 和 `packages/core/ai/provider/provider-gateway.ts` — 添加 `AbortController` + 30 秒超时
2. 添加指数退避重试（最多 3 次，针对 429/500/网络错误）
3. 添加简单的速率限制（每用户每分钟 20 次 AI 请求）

**验收**：AI 提供商挂起时 30 秒内返回错误而非永久阻塞；并发请求不会耗尽 API 配额。
