# Release Notes v0.7.11

**发布日期**: 2026年11月3日

OpenLearn V2 **v0.7.11** 是紧随 v0.7.10 发布的重要安全加固、规范治理与稳定性补丁版本。本版本重点落地了 **AI Provider 账号级数据隔离与防越权调用（Issue #383）**、**AI Agent 协作与开发规范（Issue-First 与 PR 驱动）**、课堂学情简报常驻归档通道、白板 PPTX 翻页死循环闪动治理（Issue #381）、教室内插件高频轮询独立限流分流，以及全新编撰的《快速上手手册》（Issue #384）。

> **版本速览**：本次发布包含 1 项新增数据库迁移（`045_ai_providers_owner_and_scope.sql`），平台主包版本升级至 `v0.7.11`。`@openlearn/plugin-sdk` 保持为 `3.8.0`，`@openlearn/plugin-test-kit` 保持为 `3.3.3`。

---

## 一、AI Agent 规范化协作与研发准则确立

为了应对大模型编码助手在自动化协作中的潜在风险，保障平台主分支代码纯净度与变更可溯源性，本版本在 `AGENTS.md`、`CLAUDE.md` 与 `docs/contributing/contributing.md` 中全面确立了 AI Agent 的开发与协作准则：

1. **问题驱动（Issue-First 流程）**：
   - 明确推荐 AI Agent 在发现系统缺陷（Bug）、安全漏洞、性能劣化或构想新功能时，优先通过 GitHub Issue（`gh issue create` 或 Web 界面）进行记录与方案论证。
   - 规范 Issue 结构：明确复现路径、预期与实际表现对比、根因分析及推荐实现方案。
2. **分支隔离与 PR 驱动（PR-Driven 协作）**：
   - **严禁直接向 `main` / `master` 主干分支提交或推送代码**。
   - 每次任务必须建立形如 `codebuddy/<issue-id>-<slug>` 或 `cursor/<slug>` 的专用工作分支。
   - 遵循 Conventional Commits 提交规范；PR 必须绑定 Issue、详述改动要点并给出完整的测试计划，前端变更强制附带实拍截图证据。
3. **本地全套质量门禁（Pre-PR Quality Gates）**：
   - 提交 PR 前本地必须完整通过代码格式检查（`pnpm format:check`）、类型检查（`pnpm lint` / `pnpm lint:strict`）、Lint 预算控制（`scripts/check-lint-budget.mjs`）、自动化测试（`pnpm test`）及 Sphinx 文档构建（`scripts/build-docs.sh`）。
4. **人类授权合并守卫（Human-Authorized Merge & Close）**：
   - 严禁 AI Agent 自主合并任何 PR；必须在人类开发者审查并发出明确合并指令后，采用 Squash Merge 方式合入主干并清理分支。

## 二、AI Provider 账号级数据隔离与越权防护（#383）

### 2.1 背景与漏洞根因

旧版本中 `ai_providers` 数据表未设计账号归属标识，导致所有配置的 OpenAI 兼容提供商（含已加密存储的 API Key）在系统内处于完全共享状态。任意登录的教师账号均可使用下拉菜单、AI 问答助手、课表 OCR 识别、学期评价等功能直接调用其他教师配置的模型，甚至可能在连通性测试接口中探测其他账号配置的掩码密钥。

### 2.2 数据库迁移（Migration 045）

- 新增 `migrations/045_ai_providers_owner_and_scope.sql`：
  - `ai_providers` 增加 `owner_id TEXT`（账号归属）与 `is_shared INTEGER NOT NULL DEFAULT 0`（全校共享标识）；
  - 建立联合复合索引 `idx_ai_providers_owner_shared` 优化访问决议；
  - 存量无归属记录平滑迁移归属于系统首个超级管理员，默认为私有，保证数据安全过渡。

### 2.3 核心解析器与严格鉴权

- **单一决议服务（`packages/core/di/ai-provider-resolver.ts`）**：
  - 封装 `resolveAccessibleAiProvider(db, options)` 与 `AiProviderError`；
  - 确立「当前用户私有模型 > 平台公共共享模型」的严格分流优先级；
  - 显式指定 `providerId` 时校验访问权限，越权请求阻断并返回 403 `PROVIDER_ACCESS_DENIED`，无可用模型时返回友好提示 400 `NO_AI_PROVIDER`。
- **服务端端点全面加固**：
  - `/api/ai-providers` 增删改查仅限本人私有模型或管理员管理共享模型；
  - 连通性探测接口（`/test`）严格限制仅可测试当前用户有权访问的模型，杜绝跨账号盲测；
  - 业务调用端点（`/api/agent/chat`、课表 OCR、学期综评、教案大纲）全面提取并校验会话 `userId`。

### 2.4 教师端与管理端界面升级

- **个人中心（ProfileModal）**：教师与管理员弹窗中新增「AI 模型设置」选项卡，普通教师可直接配置与测试个人专有 API Key。
- **管理面板（AiProvidersPanel）**：清晰呈现「平台共享」与「个人私有」状态徽章，管理员支持一键切换共享属性。
- **界面下拉提示**：右侧边栏与课表 OCR 下拉框中，模型名称后方自动标注 `· 平台共享` 或 `· 私有`。

## 三、学情简报常驻「归档并结束课堂」通道（#379）

此前「归档并结束课堂」提示仅在课堂阶段切换的瞬时通知中出现，若教师通过其他路径返回学情简报，则无法便捷归档。

- `ClassroomBriefingView` 页头操作区固定常驻「归档并结束课堂」按钮。
- 点击触发二次确认弹窗，确认后调用封存接口，支持加载态防重与状态幂等处理。
- 根据最新会话状态智能提示「归档成功」或「本课节已归档」，体验顺畅闭环。

## 四、核心稳定性与并发修复

### 4.1 白板 PPTX 翻页死循环闪动治理（#381）

- **问题**：`RevealPresentationWrapper` 的换页回调在依赖未稳定时导致旧页码被反复回写，包装组件与查看器之间形成来回拉扯的无限闪动。
- **修复**：解耦回调与当前页索引依赖，使用 `Ref` 保持回调函数引用稳定，引入 `pendingPptxTargetRef` 忽略查看器内部未追上目标页时的滞后回报。

### 4.2 插件高频轮询独立限流分流（#380）

- **问题**：原全站通用写限流按客户端 IP 分桶（180 次/分），教室内多台学生机同一出口 IP 的插件轮询（如便签 3 秒轮询）迅速占满配额，导致教师端切页与白板保存被 429 报错打断。
- **修复**：
  - 插件 API（网关 REST 及沙箱命令）分离至独立限流桶 `pluginApiLimiter`（按会话隔离，600 次/分/会话）；
  - 插件网关限流键调整为「登录身份优先，匿名回落 IP」；
  - 前端白板写入补齐 429 友好提示与防刷抖动保护。

## 六、升级指南与数据库迁移

### 6.1 自动迁移执行

从 v0.7.10 或更早版本升级至 v0.7.11 时，系统启动时将自动检测并执行 SQLite 迁移文件：

```text
migrations/045_ai_providers_owner_and_scope.sql
```

该迁移为幂等设计，存量已配置模型将自动赋权给平台初始超级管理员，现有运行不会中断。

### 6.2 依赖检查

平台主包 `openlearn-next` 已更新至 `0.7.11`。若您正在开发第三方插件，建议引入当前稳定的 SDK：

```json
{
  "dependencies": {
    "@openlearn/plugin-sdk": "3.8.0"
  },
  "devDependencies": {
    "@openlearn/plugin-test-kit": "3.3.3"
  }
}
```
