# Release Notes v0.7.2

**发布日期**: 2026年10月25日

OpenLearn V2 **v0.7.2** 是平台的**沙箱边界与发布正确性补丁版本 (Sandbox Boundary & Release Correctness Patch)**。本版本收敛两类系统性缺陷 —— 一类是**插件隔离边界被绕过或形同虚设**（worker 模式原始出网不受限、`getBuiltinModule` 可绕过屏蔽名单、学生数据能力缺失只告警放行、已安装插件的出站域名既不可见也不可撤销、进程内身份开关与配额调参拼错即静默回落），另一类是**门禁与发布环节「看起来有、实际不拦」**（路由数据范围声明门禁从未启用、ESLint 告警预算与中文硬编码检查不在 CI、prettier 格式没有门禁、全量 e2e 不进 CI、覆盖率用固定阈值、发布包缺 `migrations/` 导致 `npx` 起不来、发布包缺 `plugin-net-preload.cjs` 导致第三方插件起不来、版本号与既有 tag 撞车）。同时完成一次全仓 prettier 格式统一，并把沉淀为 audit 的课程导入链路收尾（课程包支持任意教学附件、导入幂等、CSV 通道标注）。

> **v0.7.1 → v0.7.2 共 47 个提交**，跨 517 个文件。

## 一、插件沙箱边界：出网管控与绕过入口

此前 worker 隔离模式下的原始出网并不受控，且存在多个绕过入口 —— 这一批修复把「worker / process 两种隔离模式同口径封锁原始 socket 与 DNS」落到实现。

1. **worker 模式出网管控**（Issue #237）：`thread` 模式由 bootstrap 的 net-guard section 封锁原始连接与 DNS，`process` 模式由 `plugin-net-preload.cjs` 承担同样的封锁；`fetch` 只把**已批准域名**交给宿主 IPC 代理出站。
2. **屏蔽 `getBuiltinModule` 绕过**：低层绕过入口 `process.getBuiltinModule` 已列入 process-masking 屏蔽名单，不再能取到 `net` / `dns` 等内置模块绕开沙箱。
3. **运行时能力判定改用「已授予」能力集**（Issue #224）：不再按插件**声明**的能力放行，而是按管理员实际已审批（已授予）的能力集合判定。
4. **学生数据能力缺失改为真正阻断**（Issue #225）：此前只告警放行，现直接阻断插件对学生数据的访问。
5. **插件打包的相对导入必须限制在插件目录内**（Issue #218）：ESM loader 拒绝逃出插件目录的相对导入（含经符号链接逃逸），杜绝插件读取宿主文件。
6. **测试**：新增 `plugin-trust-boundary-network-modes.test.ts`（两种隔离模式的网络口径、preload 装配验证）、`plugin-audit-poc.test.ts`（越权与路径逃逸用例）。

## 二、插件出站域名授权闭环与可撤销（R-02）

审计把 R-02 记为「安装/启用 UI 未突出展示 allowlist」，复查后发现缺口更大：`approvePluginNetHosts` 在整个仓库里**没有任何调用方** —— 授权链路本身不存在，第三方插件的出站白名单永远是空的。

1. **授权链路补齐**：安装/更新（`upload-zip-raw` / `update-zip-raw` / `install-from-url`）接受 `x-approve-network-hosts`，把清单 `network.outbound` 中**通过归一化**的域名写入 `plugin_network_grants`；响应把「清单声明」「已授权」「永远不可批准（带原因）」三类分开返回，避免把「声明了」误当成「已授权」。
2. **已安装插件的出站域名可见可撤销**：新增管理员接口 `GET /api/plugins/:id/network-grants`（提案 / 已批准 / 已拒绝）、`POST`（批准）、`DELETE`（撤销），均写 `plugin.network_grant_approved` / `_revoked` 安全审计；撤销返回「是否真的删掉了一行」，不把「本来就没有」当成功。
3. **拒绝有原因**：新增 `classifyNetHostProposals` —— 回环/私有/保留地址、通配符、带协议或端口的写法各自给出具体原因，而不是静默消失。
4. **安装向导**：出站域名逐条展示（默认**不勾选**），不可批准的项单独列出并注明原因。

## 三、启动期强校验：把「拼错即静默回落」变成 fail-fast

多个开关与调参键此前对非法值是**静默回落默认** —— 运维以为放宽了配额，实际没生效。

1. **进程内身份开关的运营面护栏**（R-01 复核）：`OPENLEARN_ENFORCE_PLUGIN_ISOLATION` 只接受 `1` / `0`，写 `true` / `yes` / `on` 一律**拒绝启动**；`OPENLEARN_TRUSTED_INLINE_PLUGINS` 在生产环境出现时启动日志必留一条可检索告警（写明这些插件与宿主共享网络栈、出站拦截对它们不生效）。
2. **插件资源配额与探活调参纳入强校验**（R-03 复核缺口）：`OPENLEARN_PLUGIN_MAX_RSS_MB` / `_CPU_QUOTA_MS` / `_CPU_WINDOW_MS` / `OPENLEARN_PLUGIN_QUOTA` / `OPENLEARN_WORKER_LIVENESS_*` 逐个校验 —— 带单位、负数、非正整数一律拒绝启动（并说明会静默回落）；窗口过短（<1000ms）只告警。
3. **CLI 子命令复用启动期环境校验**（R-05）：`openlearn-next doctor` 等子命令同样走这套校验，避免「命令行说环境没问题、实际起服务就失败」。
4. **测试**：`env-validation.test.ts` 新增 13 例（合法值矩阵、带单位与负数被拒、开关拼错 fail-fast、探活调参必须正整数、生产环境信任名单产生带代价说明的告警但不阻断）。

## 四、认证、授权与数据范围门禁

1. **路由数据范围声明门禁启用**（Issue #229）：服务端启动时审计所有「已认证但未声明数据范围」的路由；此前 `ROUTE_SCOPE_ENFORCE` 从未被设置过，**门禁形同虚设** —— 新增路由不声明数据范围不会被任何人发现。现在 CI 全局启用，漏声明直接让服务器**起不来**。
2. **口令摘要统一 bcrypt**（Issue #227）：`user.create` / `user.update` 此前不走 bcrypt，改为与种子账号、名册入口同源。
3. **统一会话角色判定口径**（Issue #226）：管理员账号不再被路由守卫误拒。
4. **active-sessions 归属裁剪 + 投影收窄**（Issue #241）：会话列表不再泄露他人数据。
5. **学生会话视图剥离 `checkin_code`**（Issue #239）：签到码不再下发到学生可见的投影里。
6. **链接协议白名单统一**（Issue #228）：写入侧与渲染侧收敛到同一套 `href` 协议白名单。

## 六、课程包与课程导入

1. **课程包支持任意教学附件**（课程导入审计收尾）：附件类型放开到 `pdf / pptx / docx / xlsx / zip / png / jpg / md / txt / csv`，每种都过 `validateMagicBytes` 签名校验，且校验用**声明的 `contentType`** 而非用户提供的 filename（否则「filename 写 .txt、contentType 报 pdf」即可绕过）；纯文本类型额外拒绝含 NUL 字节的内容。刻意**不加**「任意二进制」桶。
2. **白板侧引用机制**：PDF/PPTX 仍内联渲染，其余类型在导入时把「课件演示」元素降级为 `fileType: 'file'`，由 `RevealPresentationWrapper` 渲染成下载卡片（教师可「移除引用」，学生看不到该入口）。
3. **导入幂等（G-06）与 CSV 多行解析（G-05）**：去重键按创建者作用域计算 —— `meta.id` 优先，否则退回规范化内容的 `sha256`；命中重复返回 `409 COURSE_PACKAGE_DUPLICATE` 并带回已存在课程。CSV 改用与学生/班级导入同源的 `splitCsvLine` 状态机，新增 `splitCsvRecords` 按引号奇偶性判断记录边界（此前逐物理行解析会把带 Markdown 换行的正文撕成两半，后半段被**静默丢弃**）。
4. **CSV 通道明确标为「简易导入」**：导入框 schema 区标题与副标题写明两条通道的分工 —— 完整课程用课程包 JSON，CSV 只做批量建空壳。
5. **体积上限对齐产品承诺**（Issue #246）：附件失败不留孤儿记录。

## 七、CI 与质量门禁：从「有脚本」到「有拦截」

这一批的共同点是：门禁脚本早就在仓库里，但**没有一条真正挂在 CI 上**，因此形同虚设。

1. **ESLint 告警预算接入 CI 棘轮**（Issue #231）：此前 `lint:eslint` 完全不在 CI，6186 条告警（`no-explicit-any` 占大头）可以无限增长；现在超过 `config/lint-budget.json` 基线即红，基线只能往下走。
2. **中文硬编码检查进 CI**：package.json 里一直有 `lint:i18n`，此前同样不在 CI。
3. **prettier 格式门禁**（Issue #236）：统一全仓格式，并把 `prettier --check` 接入 CI。**2026-10-25 起改为全仓基线棘轮**（`scripts/check-format-budget.mjs` + `config/format-budget.json`）：此前门禁只检查「本次变更触及的文件」，文件一旦合入 main 就再也不会被检查 —— 实测 5 个不合规文件让三次 main push 转红后，HEAD 的 CI 却 11 个 job 全绿，「CI 绿」是不真实的。零基线之后整仓检查不再惩罚无关 PR（不合规只可能由某次提交引入，那次提交对应的 PR 就是第一个失败的地方），基线清单当前为空 —— **全仓必须合规**。
4. **覆盖率棘轮替代固定阈值**（Issue #232）：覆盖率不再用固定门槛，改用可升降的基线棘轮，并把运维脚本纳入分母。
5. **全量 e2e 进 CI**（Issue #230）：此前 CI 只点名跑 6 个 spec（26 个里的 23%），课堂互动、并发一致性、教师工作流等核心链路的 e2e 从不在 CI 运行，回归只能靠人工点。
6. **依赖漏洞清零**（Issue #235）：升级 vitest 到 4.1.12，`pnpm audit` 告警清零（CI 的 security-audit 作业以 `high` 为阻断阈值）。
7. **功能巡检**（`pnpm sweep`）：全角色遍历所有视图入口，收集未捕获异常、导航失败与任何 4xx/5xx 响应；本版本补齐课堂互动、课件成绩、课程包三条**写剧本**与跨教师授权回归（Issue #247）。

## 八、发布正确性与运维安全基线

### 8.1 发布包缺文件（两个 P0，均已修复）

1. **缺 `migrations/`**（Issue #283）：`npx openlearn-next` 在用户目录启动直接 FATAL —— `files` 清单没带迁移目录，且 `getDefaultMigrationsDir()` 写死「上溯三级」只在源码布局成立，打包成 `dist/server.cjs` 后已到包外。修复为「`OPENLEARN_MIGRATIONS_DIR` 覆盖 → 从模块位置向上找包根 → `cwd/migrations` 兜底」，`server.ts` 复用同一解析器；同一缺陷也让 CLI 的 `migrate status` / `migrate rollback` 必然 `MODULE_NOT_FOUND`，一并改为加载 `dist/cli-migrator.cjs`。
2. **缺 `dist/plugin-net-preload.cjs`**：第三方插件被策略强制降级到 `process` 隔离模式，而该模式靠这个 preload 脚本封锁原始 socket / DNS。包内没有该文件时，`resolveNetPreloadPath()` 的四个候选路径全部落空（`import.meta.url` 那条被 **esbuild 在 CJS 产物里 shim 成 `{}`** 而永久失效），函数 fail-closed 直接抛 `[PluginNet] preload script not found` —— **插件根本起不来**。CI 抓不到是因为它跑在仓库源码布局下，`cwd/dist/...` 恰好命中本地构建产物。修复为：`files` 补入该文件 + 解析器支持注入解析起点（对齐 `getDefaultMigrationsDir` 的既有模式）+ 新增 5 例护栏测试 + 新增 `scripts/verify-packaged-plugin-preload.mjs` 端到端脚本（正反两组结果都可复现）。

### 8.2 版本号占用与发布脚本可验证

`package.json` 版本此前仍是 `0.7.1`，而 `v0.7.1` 这个 tag 已存在（指向 47 个提交之前），npm 上 `openlearn-next` 最新是 `0.6.0` —— 直接发布会把「47 个提交之后的内容」以 `0.7.1` 的名义发出去，tag 与 npm 包指向**不同的代码**。本版本升到 `0.7.2`（同步 `package.json` 与 `packages/core/version.ts` 的 `FALLBACK_VERSION`），并给 `scripts/publish.sh` 补上 `--dry-run` 模式与**版本占用前置门禁**（版本号已被 git tag 或 npm 占用时直接拒绝发布）。

### 8.3 运维安全基线

1. **敏感文件权限基线自检**（Issue #233）：`.env`（含 `ENCRYPTION_KEY`）、SQLite 主库与 `backups/` 下的全部快照等价于全量学生数据，默认 umask 下落在 644（全局可读）。启动期做一次自检并打 WARN（不阻断启动），部署后可跑 `pnpm ops:check-perms`。
2. **备份落盘即 600**、**pre_migration 快照纳入保留策略 + 创建即 600**（Issue #234）。
3. **平台自建产物「创建即合规」**：此前基线只负责**检查**，而平台自己创建这些文件时用的是默认 umask —— 主库与 WAL/SHM 侧车落在 644、备份目录落在 755，于是「门禁在自己的开箱状态下就是红的」：全新部署启动即报 2 条 ERROR，`pnpm ops:check-perms` 直接以退出码 1 失败。现改为创建即合规（文件 `open(..., 0o600)`、目录 `mkdir(mode: 0o700)`，不依赖 umask，也没有「先宽后紧」的暴露窗口），覆盖主库、WAL/SHM 侧车、备份目录、恢复前的安全副本与恢复覆盖后的主库；**基线同时补上了此前漏检的 WAL/SHM 侧车**（侧车在 WAL 模式下装着尚未 checkpoint 的全量学生数据，「主库 600 + WAL 644」等于没设防）。
4. **既有部署一步 remediation**：`pnpm ops:check-perms --fix` 按基线收紧（文件 600 / 目录 700）。`.env` 属用户自写文件，启动期不会自动改，只能经该命令显式处理。

## 九、验证与升级说明

1. **验证**：全量 `pnpm test` **597 文件 / 4941 例通过（3 skipped）**；`pnpm lint`（`tsc --noEmit`）与 `pnpm lint:strict` 均 0 error；ESLint 告警预算 6243 条（未超基线，新增文件 0 告警）；`pnpm audit --audit-level high` 0 漏洞；文档漂移审计 0；CI 11 项作业全绿（含 `typecheck-and-test`、`Browser workflow E2E`、`E2E full coverage`、`Public beta journey`、`Feature sweep (all roles)`、`coverage`、`security-audit`、`Docker release rehearsal`、`Upgrade regression`）。
2. **发布形态自检**：`npm pack` 产物 **114 个文件**，按 `files` 清单还原后启动 → 迁移 44 个文件就绪、`OpenLearn Next v0.7.2 ready`；包内 preload 可真实加载并拦截原始 socket。
3. **迁移**：本版本不含新增迁移文件（沿用 v0.7.1 的 `040`–`043`）。
4. **行为变化（请留意）**：
   - 未受信任的第三方插件现在**一律**以 `process` 模式运行并受出网管控；管理员若要在进程内运行，必须显式写入 `OPENLEARN_TRUSTED_INLINE_PLUGINS`（生产环境启动日志会留告警）。
   - `OPENLEARN_ENFORCE_PLUGIN_ISOLATION` 与插件配额/探活调参键现在**只接受严格取值**，写错会让服务**起不来**（这是有意的 fail-fast，请按 `.env.example` 修正）。
   - 新增路由若未声明数据范围，CI 与生产启动都会**直接失败**（`ROUTE_SCOPE_ENFORCE=true`）。
5. **插件作者**：本版本未改动 `@openlearn/plugin-sdk` 的公开类型（SDK 版本独立发布，当前仍为 3.7.0）。`engines.openlearn` 约束为 `>=0.2.5` 的内置插件对 0.7.2 全部兼容。
