# Release Notes v0.7.1

**发布日期**: 2026年10月23日

OpenLearn V2 **v0.7.1** 是平台的**课堂授权与成绩链路一致性补丁版本 (Classroom Authorization & Grade Integrity Patch)**。本版本收敛了课堂实时链路的两类系统性缺陷 —— 课堂交互路由只校验角色不校验对象（任意教师可操作他班进行中的投票/抢答/倒计时，任意学生可凭 `lessonId` 读取他班会话与正确答案）、课堂与学生数据事件经常驻房间与全局广播扩散到全平台；并把成绩链路从「六七条各自为政的写入路径」收敛为**唯一写入入口**：稳定关联、学年口径、写入边界、结构化日志，以及带历史留痕的手动分/缺考保护。同步修复了 v0.7.0 成为升级基线后暴露的升级回归门禁与浏览器 E2E 的稳定性问题。

---

## 一、课堂交互的对象级授权与答案脱敏

此前课堂路由（会话、投票、抢答、倒计时、节奏、结课通票、大屏数据）多数只校验「你是教师/你是学生」，不校验「这个会话是不是你的」。多教师部署下，任意教师可操作他班进行中的课堂；任意学生可凭 `lessonId` 读取其他班级的进行中会话、投票正确答案与动态流回放（其中含其他学生姓名）。

1. **统一判定链**：`server/services/class-access.ts` 新增 `authorizeClassroomControl` / `authorizeClassroomRead`，把会话 `teacher_id`、绑定班级 `owner_user_id`、课节 `creator_id` 收敛成同一条判定；写操作要求可控制，读操作要求可控制或在班。
2. **逐条接入**：课堂路由全部改为经该判定，投票 / 抢答 / 通票同时校验「实体所属会话」与「课节」一致，阻断跨课节拼装。
3. **响应侧脱敏**：学生端会话响应不再下发 `settings_json`（教师侧配置）与教师用的 `feedReplay`（含其他学生姓名）；极速投票的 `correct_option` / `correctOption` 一并纳入答案字段脱敏，只在教师侧可见。
4. **兼容既有行为**：无明确归属人的历史会话、`creator_id` 为空的课节保持开放；已归档会话不阻塞下一节新会话；未绑定班级的自学/演示课堂对已登录学生保持开放。
5. **测试**：新增 `server/__tests__/classroom-authorization.test.ts`（6 条：跨班读/写拒绝、学生答案脱敏、跨班投票拒绝等）。

## 二、课堂与学生数据事件的房间定向投递

`classroom-broadcast` 常驻房间让**每个**客户端都加入，于是每节课的倒计时、投票、抢答与动态流被推给了全平台；另有 11 处「幽灵房间 + 紧跟一行全局 `io.emit`」的双投结构。

1. **房间口径唯一真源**：`server/presence.ts` 提供 `classroomEventRooms(lessonId, target)` / `emitClassroomEvent(io, lessonId, EVENT, payload, target)`，按 `ClassroomEventTarget { classId?, userIds?, staff? }` 取并集投递；`userRoom(userId)` 个人房间按 `session.userId` 在连接时自动加入，客户端 `join-room` 一律拒绝。
2. **删除常驻房间**：移除 `classroom-broadcast`，可达性由班级房间承接；伪课节（`assignment-*-student-*`）经 `isRealLessonRoom()` 只投自身房间，不向外扩散。
3. **替换而非新增**：删除那 11 行全局 `io.emit`，由 `emitClassroomEvent` 一次性投递 —— 只改房间名而不删全局广播会让同一事件推送两次，这是本次改造最容易踩的坑，已在实现中一并规避。
4. **投放口径**：课堂状态 → 课节 + 班级房间；点名/积分/已读回执 → 对应学生个人房间（监控类同时投 `presence-staff`）；作业评分 → 仅被评分学生；学生端错误 → 仅 `presence-staff`。

## 三、课件成绩的稳定关联、学年口径与写入边界

1. **稳定关联**：自动录入 / 缺考标记 / `isPromoted` 不再用「`互动课件: {课件名}` 标题 + 课节/班级」定位作业，改为匹配 `assignments.content` 中的 `{"type":"interactive_courseware","coursewareUuid":"..."}` 标记（SQLite `instr()` 匹配，避免 `json_extract` 在脏数据上抛错）。课件改名不再让历史成绩断链另建作业；同课节两个同名课件不再互相覆盖成绩。
2. **学年口径**：运行时自动创建的课件作业、成绩行与 `student_lesson_progress` 现在都写入 `academic_year`（取值链：课堂会话 → 排课学年 → 排课日期推导 → 当前学年），重跑时用 `COALESCE` 保留已有学年，并回填历史空值。此前这些行常年为 `NULL`，在按学年过滤的学期报表与学年对比里直接消失。
3. **写入边界**：手动录入成绩前校验学生确在目标班级内（新增 `student-not-in-class` 拒绝原因），阻断把 A 班学生的课件成绩写入 B 班；对不存在的 attempt 提交返回 404，不再落下一批永远无法归属的孤儿 `submission_raw` / `submission_result` 行。
4. **测试**：`auto-record-score` 新增 7 例（排课学年、日期推导学年、改名复用同一作业、同名课件各自独立、非在班学生拒绝、缺考行学年、考勤联动缺考行学年），`courseware-attempts-filter` / `courseware-submit-actor` 补充 UUID 标记区分与 404 零落库断言。

## 四、成绩写入收敛为唯一入口：审计历史与手动分/缺考保护

成绩此前有六七条写入路径（课件自动录入、教师手动录入与补录、教师标记缺考、考勤联动缺考、AI 批改、作业中心插件、学期成绩同步、`assignment-eval` 投影），各自散落 `INSERT ... ON CONFLICT` / `UPDATE`。保护规则只在两处各写一份，学期成绩同步与插件投影仍会静默覆盖教师手动分；改分之后没有任何记录能回答「谁在什么时候把它从多少改成了多少」。更隐蔽的是重新提交作业：`assignment.submit` 的冲突更新会把已批改行打回 `submitted`，学生重交即可冲掉待复核成绩。

1. **单一入口**：新增 `packages/core/db/assignment-grade-writer.ts`，所有改分路径（含插件）统一调用 `applyGradeChange`，在**单个事务**内完成「读旧值 → 保护判定 → upsert → 写历史」。
2. **保护矩阵**：非 manual 来源（auto/ai/system/plugin）不得覆盖 `source` 为 manual/plugin/历史 NULL 的已出分行（`manual-protected`），也不得改判缺考行（`absent-protected`）；同来源刷新（ai→ai、plugin→plugin）与对自动分的覆盖仍允许；学生刚提交、尚未出分的行不触发保护，AI/自动批改照常工作。仅教师/管理员可经 `overrideProtected` 越过保护（`ai.apply_grade` 新增 `overrideManual`，只对特权 actor 生效）。
3. **审计留痕**：迁移 `040_assignment_grade_history.sql` 新建 `assignment_grade_history`（旧/新分数、状态、来源、actor、reason、时间）与索引，并给 `assignment_submissions` 增加 `graded_by`。只有分数/状态/来源真正变化才写历史（null→0 视为变化），幂等重写不产生噪音。
4. **口径**：分数取整并限定 0~100，缺考之外不允许空分；`createIfMissing=false` 时缺行返回 `submission-not-found`，作业不存在返回 `assignment-not-found`。
5. **重交不降级**：`server/services/assignment-service.ts` 与 `management` 插件的 `assignment.submit` 冲突更新改为 `CASE WHEN status IN ('graded','absent') THEN status ELSE 'submitted' END`，重交只更新作答内容，不把已批改/缺考行打回待批改。
6. **测试**：新增 `server/__tests__/grade-audit-history.test.ts`（9 条，跑真实迁移）覆盖 actor 与历史序列、保护矩阵、override、缺考、submitted 行批改、分数越界与缺行/缺作业；`ai-planner` / `management` / `assignment-hub` / `semester-grade` / `auto-record-score` / `assignment-service` 补齐历史与保护断言。

## 五、成绩链路可观测性

「为什么这条成绩没录上」此前只存在于客户端响应里：学生看到成绩没更新、教师点完批量补录没有变化时，服务端没有任何可检索记录。

1. **手动录入**（`CoursewareService.promoteAttempt`）：成功输出 `[courseware.promote] recorded` + `{attemptId, studentId, lessonId, classId, assignmentId, score}`；拒绝输出 `[courseware.promote] rejected` + `reason`（`warn` 级），与返回给教师的 422 文案同源。
2. **实时自动录入**（`submitAttempt`）：非预期跳过 `student-not-in-class` / `attempt-not-found` 走 `warn`，保护类（`manual-protected` / `absent-protected` / `not-higher`）走 `info`；规则未开启、未完成、无分数等**预期**跳过不输出，避免淹没真正的异常。
3. **批量补录**（`autoRecordForLesson`）：每次教师点击输出一行 `[courseware.auto-record]` + `{recorded, skipped, absentGenerated, reasons}`，`reasons` 按跳过原因聚合；返回类型由 `any` 收紧为 `AutoRecordReport`。
4. **隐私**：日志只含内部 ID，不含学生姓名与作答内容。
5. **测试**：新增 `server/__tests__/grade-academic-year-visibility.test.ts`（3 条）—— 手动录入按排课学年落库且只在对应学年可见、课件改名后重录复用同一作业行、批量补录对手工成绩给出 `manual-protected` 原因分布并可从日志还原摘要；日志断言直接解析结构化字段，不依赖自然语言文案。

## 六、升级回归门禁与浏览器 E2E 的稳定性修复

1. **升级回归 fixture 被签名门禁阻断**：v0.7.0 成为「上一正式版」基线后，「Upgrade from last release」（每个 PR 与 main 推送都跑）与 tag 上的「Publish release fixture」作业转红 —— `scripts/upgrade-regression/lib.ts` 上传本地构建的测试插件 ZIP 时未声明 `x-allow-unsigned`，被 v0.7.0 起生效的插件签名门禁拒绝。修复为显式携带 `x-allow-unsigned: true`（本地自建 fixture 正是门禁所述的「本地可信插件」场景，对尚无此门禁的旧 tag 服务端必须接受），并新增单测钉住该请求头。
2. **E2E 断言中途被整页刷新打断**：`server.ts` 给 Vite 开发服务器传的内联 `server.watch: {}` 与 `hmr: { server }` 覆盖了 `vite.config.ts` 中「`PLAYWRIGHT_TEST` / `DISABLE_HMR` 时关闭监听」的策略（`mergeConfig` 遇到「文件侧 `null`、内联侧对象」直接采用内联值），于是 E2E 写 SQLite 时 WAL 变动 → 触发 full-reload → 页面在断言中途被刷新。修复为不再内联 `server.watch`、`hmr` 与同一套开关保持一致；`e2e/lesson-classroom-flow.spec.ts` 的 `courseHasSegment` / `courseHasElement` 吞掉瞬时网络错误并返回 `false`，让 `expect.poll` 能重试到条件成立。修复前该作业 5 passed / 6 failed、期间触发 93 次整页刷新；修复后 11 passed / 0 failed、0 次刷新。

## 七、验证与升级说明

1. **验证**：全量 `pnpm test` **571 文件 / 4695 例通过（3 skipped）**；`pnpm lint`（`tsc --noEmit`）与 `pnpm lint:strict` 均 0 error；CI 13 项检查全绿（含 `typecheck-and-test`、`Browser workflow E2E`、`Feature sweep (all roles)`、`Upgrade from last release`、`docker-build-and-rehearse`、`coverage`）。
2. **迁移**：`040_assignment_grade_history.sql` 为**增量迁移**（新建表 + 加列，不改既有列语义），随服务启动自动执行，可重复执行。
3. **行为变化（请留意）**：升级后历史遗留的 `source IS NULL` 成绩会被回填为 `manual` —— 它们从此被视为「教师手动分」，非 manual 来源的自动改分不会再覆盖这些行。这正是保护机制的目的；若需要在升级后批量重算历史成绩，请由教师/管理员走 `overrideProtected` 的显式改判路径，改判会写入 `assignment_grade_history`。
4. **插件作者**：`ISemesterGradeService.saveSemesterGrade` 新增可选第 4 参 `SemesterGradeWriteOptions`，返回值由 `Promise<void>` 扩展为 `Promise<GradeWriteSummary | void>`（被保护拒绝时返回 `{ ok: false, reason }`）。旧调用方可以继续忽略返回值，无需改动。`@openlearn/plugin-sdk` 与平台版本相互独立，SDK 的类型变更按其自身节奏发布。
