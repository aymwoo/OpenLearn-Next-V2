# Release Notes v0.3.21

**发布日期**: 2026年9月20日

OpenLearn V2 **v0.3.21** 是一个**启动横幅品牌化与版本号单一来源版本 (Startup Banner Rebrand & Version SSOT Release)**。本版本修正了启动服务时终端横幅仍显示历史命名 "Educational OS Kernel v0.3.18" 的体验问题：将横幅统一为 "OpenLearn Next"；为本地与局域网 URL 加上 OSC 8 超链接，使现代终端可直接 ⌘/Ctrl+点击打开浏览器；同时将 `PLATFORM_VERSION` 重构为运行期从 `package.json` 读取，根治"bump 了版本却忘记同步字面量"的漂移隐患。

---

## 一、启动横幅品牌化与可点击 URL

### 1. 横幅文本统一为 "OpenLearn Next"

- **历史遗留修正**：终端启动横幅原文本为 `Educational OS Kernel v0.3.18 ready:`，与平台统一品牌命名 "OpenLearn Next" 不一致，且版本字面量长期硬编码在 `packages/core/version.ts` 中、随发布漂移。修正后横幅为：

  ```
    OpenLearn Next v0.3.21 ready:

    ➜  Local:   http://localhost:9000
    ➜  Network: http://192.168.x.x:9000
  ```

- 修改点：`server.ts` 的 `httpServer.listen(PORT, HOST, ...)` 回调中 `console.log` 横幅字符串。

### 2. 网址可点击 (OSC 8 超链接)

- **OSC 8 协议**：本地 (`Local:`) 与局域网 (`Network:`) URL 套用 OSC 8 (`\x1B]8;;URL\x1B\\URL\x1B]8;;\x1B\\`) 超链接转义。iTerm2 / Windows Terminal / GNOME Terminal / VS Code 集成终端等支持 OSC 8 的现代终端可直接 ⌘/Ctrl+点击打开浏览器；不支持的终端自动降级为纯文本 URL。同步覆盖 `OPEN_BROWSER=true` 时的 "Auto-opening browser" 提示行。
- **非交互环境安全降级**：以 `process.stdout.isTTY && process.env.TERM !== 'dumb'` 为启用前置条件。输出被重定向到文件、管道、`pm2 log`、CI 捕获等场景时不会留下 OSC 转义序列污染日志。

---

## 二、版本号运行期单一来源 (SSOT)

### 3. `PLATFORM_VERSION` 从硬编码改为运行期读取 `package.json`

- **重构**：`packages/core/version.ts` 不再持有硬编码字符串，改为模块加载时从最近的上级目录 `package.json`（要求 `name === 'openlearn-next'`）读取 `version` 字段。两条运行路径都覆盖：
  - **CJS 产物**（`dist/server.cjs`）：从 `__dirname`（指向 `dist/`）向上遍历；
  - **ESM / `tsx` 直接运行源码**：从 `import.meta.url`（指向 `version.ts`）向上遍历。
- **`FALLBACK_VERSION = '0.3.20'`**：仅在完全找不到 `package.json`（例如被打包进非标准目录）时兜底使用，绝不会"擅自"显示过时版本号。
- **发布流程简化**：从此发布新版本只需修改根 `package.json` 的 `version` 字段，启动横幅、`PlatformBuilder` 元数据、Plugin 引擎版本、插件 `engines.openlearn` 兼容性检查等所有引用点自动同步。
- **彻底消灭"v0.3.18 幽灵"**：之前多次出现"启动横幅还在显示 0.3.18 而代码早已迭代到 0.3.20"的问题，根因正是 `version.ts` 字面量忘记同步。现在该面已经被代码结构性消除。
