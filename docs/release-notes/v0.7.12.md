# Release Notes v0.7.12

**发布日期**: 2026年11月3日

OpenLearn V2 **v0.7.12** 是 v0.7.11 之后的**开发者体验与工程治理版本**，不含运行时行为变更。本版本集中解决三类「文档与契约说得对、但工具链跟不上」的问题：**权限清单缺一份可声明全集**（导致真实权限被误判为捏造串）、**Gitee 镜像同步全靠人工**（镜像过期是隐形故障）、以及 **PDF 手册制品入库导致仓库膨胀**。

> **版本速览**：本次发布不含数据库迁移，平台主包版本升级至 `v0.7.12`。`@openlearn/plugin-sdk` 保持为 `3.8.0`，`@openlearn/plugin-test-kit` 保持为 `3.3.3`。

---

## 一、权限清单落到契约层（Issue #368 的收尾）

平台 Issue #368 已把权限字符串收敛到 `packages/core/capability/catalog.ts`，但**机器可读契约没跟上**：`docs/agent/contracts/capabilities.json` 只导出三套**正交**登记（`command_required` / `method_policy` / `runtime_permission`），没有一份「哪些串能写进 `capabilitiesProposed`」的封闭答案。

缺了它，插件作者与 L0 静态检查只能靠猜，于是把真实的方法型权限（`student-data:write` / `task:register` / `grades:write` …）误判为「捏造串」并删掉——**真实事故：4 个插件的 `pointsLedger.addPoints` 全部失效**。危害在于删掉后运行期是静默 403 / `PluginCapabilityDeniedError`，比误报更难排查。

### 1.1 契约新增 `declarable` 字段

`audit-tools/agent_facts.py` 现在从 `catalog.ts` 的 `CAP` 对象抽取全量取值（含对方法级常量的解引用），生成 **31 条** `declarable` 清单，并由 `agent_facts.py --check` 在 CI 中校验。

### 1.2 能力矩阵文档补全方法级权限

`docs/reference/plugin-capability-matrix.md` 此前只列了资源型 19 条 + 仅可声明 3 条，漏掉方法级 8 条与平台内部 1 条（`segment:gate_eval`）——而 `assertValidManifestCapabilities` 的报错文案恰恰把本页当作「合法值来源」，用户按提示去查会**查不到自己写的那一条**。

同时修正两处口径错误：

- `ai:invoke` 被写成「不是 RBAC 字符串」——它**是**真实权限串（方法型），同时也属于第 2 套 `RuntimePermission`，两处都要声明；
- 统计口径写「20 个 `capabilityRequired`」——真值是 **19**，第 20 个来自 SDK `.d.ts` 的 JSDoc 注释，不是真声明。

### 1.3 AI 手册基线漂移可被门禁发现

`docs/agent/agent-handbook.md` 顶部的版本表此前写着平台 `0.7.8`，而契约 `versions.json` 是 `0.7.11`——因为前者是纯文本、没有任何校验。现已对齐，并让 `agent_facts.py --check` **一并校验该表与源码一致**。

## 二、Gitee 镜像同步自动化

仓库已有 Gitee 镜像 `gitee.com/aymwoo/openlearn-next`，但同步完全靠人工：`.github/workflows/` 里没有任何 gitee 相关 job，文档只写着「维护者合并后执行 `git push gitee main --tags`」。

问题在于**镜像过期是隐形故障**：国内开发者克隆镜像后看到的是旧文档、旧契约，却没有任何信号告诉他们镜像已经落后。而人工步骤只要漏一次就断链。

新增 `.github/workflows/sync-gitee-mirror.yml`，把三条约束编码进流程：

| 约束           | 实现                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------- |
| **单向**       | 只从 GitHub 推往 Gitee，绝不反向；`permissions: contents: read`                                 |
| **只快进**     | 推送前 `git merge-base --is-ancestor gitee/main HEAD` 判定；分叉就报错退出，**绝不 force-push** |
| **不阻塞主干** | `continue-on-error` + 未配 Secret 时自动跳过，失败不拖红无关 PR                                 |

工程细节：推送后**回读远端**比对 `refs/heads/main` 与本次提交 SHA（防「push 成功但没落到 main」的假成功）；凭据用 `http.extraheader` 传递，不写进 `.git/config`。触发时机为 `main` 推送 + 每 6 小时兜底 + 手动触发。

> 维护者需一次性配置 Secret `GITEE_USERNAME` / `GITEE_TOKEN`；未配置时 workflow 会打 notice 并正常结束。

## 三、PDF 手册制品迁出仓库，改走 Release 附件

三份手册 PDF 此前直接入库，合计 **13.3 MB**（插件开发手册 6.0 MB + Skill 使用指南 4.4 MB + 快速上手手册 2.9 MB）。每次文档改动重新导出都会再叠一份二进制进 git 历史（历史不可追回），且制品容易与源码版本脱节。更糟的是 `plugin-development-tutorial.pdf` **没有任何脚本能生成**，属于不可复现的一次性产物。

现改为：

- 仓库只保留**生成脚本 + 截图源图**；PDF 产物写入 `docs/_build/handbooks/`（已 gitignore）；
- `scripts/export-handbooks-pdf.mjs` 补上插件开发手册的目标，三份手册现在都可一键重出；
- 新增 `scripts/upload-handbooks.mjs` 与 `npm run docs:pdf` / `npm run docs:pdf:upload`；
- 文档改用 `releases/latest/download/<资产名>` **稳定链接**，后续发版只需重新上传，不必再改文档链接。

## 四、班级与学生批量导入修复（Issue #389）

- **模板示例列数对齐**：补全班级模板（8 列）与独立学生模板（6 列）的性别示例值，确保数据行列数与表头严格一致；
- **导入弹窗 i18n**：内嵌示例代码块按用户语言渲染中/英文，并补充性别列取值说明；
- **班级内批量招生支持性别**：`parseCSV` 增加 `gender` 解析，`BulkEnrollInput` 显式声明 `gender?: string`；
- **回归断言**：补充「表头与每一行示例数据列数完全一致」的守护测试。

## 五、开发者文档入口双平台化

`README.md`、`docs/index.md`、快速上手 / 安装指南 / 部署指南的克隆命令，以及插件开发教程 §2.8 的 Skill 安装命令，全部补齐 GitHub 主仓与 Gitee 镜像双地址。其中 Skill 安装特别注明：`skills.sh` 只索引 GitHub，从镜像安装必须写**完整仓库 URL**（owner/repo 简写会被固定拼成 GitHub 地址）。

协作规范（`AGENTS.md` / `CLAUDE.md` / `docs/contributing/contributing.md`）同步确立四条红线：一个变更只在一个平台开一份 Issue / PR、镜像只快进不 force-push、禁止 Gitee 侧自动双向镜像、issue / PR 编号不跨平台复用。
