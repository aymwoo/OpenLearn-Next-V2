# Release Notes v0.7.5

**发布日期**: 2026年10月27日

OpenLearn V2 **v0.7.5** 是平台的**插件扩展点治理版本**。本版本的主线只有两件事：把两类「插件停用后仍在生效」的幽灵扩展点从根上修掉，以及把一批「文档说了、代码没做」的缺口变成会红的门禁。

> **v0.7.4 → v0.7.5 共 92 个提交、198 个文件（+12,588 / −3,281）**。不含新增数据库迁移（沿用 44 个 `.sql`）。

---

## 一、插件扩展点不再出现「幽灵」

两个缺陷**同一根因**：有些注册表是插件用 `ctx.resolve(token)` **直取**的裸注册表，不像 `ctx.services.*` 那样经过 `ResourceTracker` 包装 —— 于是停用/卸载时 `disposeAll()` 拿它们没办法。插件代码已经卸载，注册项却还在注册表里继续生效。

### 1.1 服务端题型注册表（Issue #320）

- **现象**：插件注册的题型在停用后仍留在注册表里 —— 教师继续能出题、继续按**旧闭包**判分，`GET /api/assessment-question-types` 也继续把它列给前端；重装/升级插件时 `registerQuestionType` 抛 `duplicate question type`，表现为「升级后插件激活失败」，必须重启宿主才能恢复。
- **根因**：全仓 `clearOwnedQuestionTypes` / `unregisterQuestionType` 此前**只有定义、零调用方**。前端一侧本来就会 `clearOwned`，服务端不清理，形成「同一扩展点两种回收语义」。
- **改法**：新增 `revokePluginQuestionTypes(pluginId, manifestId)`（与既有 `revokePluginStageGuards` 同构），按「安装行 UUID」与 `manifest.id` 两个 owner 各清一次（幂等），接到 inline 正常停用 `finally`、inline pipeline 崩溃兜底、worker/process 停用 `finally`、uninstall 四条清理链。

### 1.2 课堂阶段门禁与课堂互动提供者（Issue #327）

这个比 1.1 更难修，因为它**没法靠猜 owner 清理**：

| 障碍                  | 说明                                                                                                                         |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| owner 是插件自选      | `registerStageGuard(owner, guard)` 的 owner 不像题型注册表的 `pluginId` 由宿主注入，宿主无法枚举「这个插件注册了哪些 owner」 |
| descriptor 不带 owner | `QuickActivityDescriptor` **没有 owner 字段**，`listActivityProviders()` 只返回 descriptor 值 → 宿主拿到它**无法反查归属**   |

- **关键观察**：这两个 token **都不在 `ctx.services` 里**（那 9 个键里没有它们），插件拿它们的唯一途径是 `ctx.resolve(token)`。所以「在 `ctx.services` 层包一层」完全无效，唯一可行的 seam 在 **resolve**。
- **改法**：新增 per-plugin 代理（`wrapClassroomLifecycleService` / `wrapInteractionRuntimeService`），记下插件**实际传入的** owner 与 id 并登记进 `ResourceTracker`，停用/卸载时精确注销 —— 不需要猜，零漏网。Token 对象与**字符串名**两条路径都接入，否则按名字解析的插件会绕过拦截。
- **不改任何公开类型，插件侧零改动。**

**验证**：两组回归测试共 6 条（停用后消失、按名字 resolve 同样被回收、卸载回收、再激活不冲突、内置题型不受影响），并各做了**负向对照** —— 撤掉修复后用例必红（`expected true to be false` / `expected { type: 'ext-quiz:demo' } to be undefined`）。

## 二、SDK 3.7.1 → 3.7.4：三次发布，三个真实事故

平台版本独立于 SDK；本版本区间内 SDK 连发三个版本，每一个都在修一个「装得上、跑不起来」的问题。**当前 SDK 为 3.7.4**。

### 2.1 3.7.1 已在 npm 上弃用（`npm deprecate`，不撤包）

该版本 `dist/index.js` 残留 5 处 `node:` 静态导入（`fs` / `path` / `url` / `crypto`，产物 75 KB）。凡是把 SDK 内联进 worker bundle 的第三方插件，运行期必然失败。装法改为 `npm i -D @openlearn/plugin-sdk@3.7.4`。

### 2.2 3.7.2：修掉 `node:` 静态导入回归

3.7.1 值导出了 7 个宿主内部类，导致 `packages/core` 实现链（含 `core/version.ts` 的 `import fs from 'node:fs'`）被内联，产物从 18 KB 涨到 75 KB。修复方式是把这 7 个类改回类型导出，并在 `build.mjs` 与契约测试里各加一道守卫。

### 2.3 3.7.3：`build` 拦住 `migrations/` 的静默失效（Issue #321）

宿主确实会在插件激活前执行 `<pluginDir>/migrations`，但官方 CLI 的 ZIP **只打包** `index.js` / `manifest.json` / `frontend.js`。两边都对，是分发链路把中间截断了 —— 作者按文档写了 `migrations/001_*.sql`，会经历「构建成功 → 安装成功 → 激活成功 → 首次执行 SQL 才报 `no such table`」。

现在 `build` 检测到 `migrations/` 目录会打印告警并指路 `ctx.db.ensureTable()` + `ctx.db.migrate()`。**刻意不改变打包契约** —— 这是提示，不是静默改行为。

### 2.4 3.7.4：frontend 产物不得残留裸模块说明符

远程插件的前端跑在不透明源 iframe 里，没有 `node_modules` 解析链。`build` 现在会在构建期拦住 frontend 产物里的裸模块说明符，而不是等运行时抛 `Failed to resolve module specifier`。

## 三、插件文档：从「只讲 UI 槽位」到「9 个扩展点全索引」（Issue #322）

审计发现一个结构性偏差：**9 个真实的「插件可注册领域扩展点」里，有 6 个在 `docs/plugin/` 与 `docs/tutorials/` 下一次都没出现**，其中 3 个只出现在 `docs/architecture/` 下。第三方作者据此形成的合理结论是「平台只支持 UI 槽位」。

- **文档**：`docs/plugin/extension-registry.md` 新增 §0 三类扩展面、§0.1 九行注册表总索引（获取方式 / 注册注销 API / 回收路径 / **可用范围**）、§0.3 九节逐个上手（最小示例 + 回收时机 + 常见错用）。
- **门禁**：新增 `audit-tools/extension_points_coverage.py`，接入 `audit-tools/run.sh` 第 2.8 段。真值**从源码推导**（`PLUGIN_RESOLVABLE_TOKENS` + 各接口体里的 `register*` 方法），不靠人手维护 token 清单 —— 上一版索引表本身就是漏的，人工清单必然腐化。豁免必须指明覆盖文档且门禁核对该文档确实提到该方法。
- **门禁上线当天就抓出 3 个漏登记的扩展点**（`registerStageGuard` / `registerActivityProvider` / `registerAIContextProvider`）与 1 条失效豁免。

同区间还补了：远程前端的**网络死区**（沙箱 CSP 是 `connect-src 'none'`，实时同步只能轮询）、`commandType` 的三种前缀语义、扩展槽位文档从 100 → 120 个成员、以及文件级预览扩展槽位。

## 四、发布链路自身的加固

0.7.3 那次「`workspace:*` 被直接 `npm publish` 带进产物、整个版本装不上」的事故，本区间继续补了三道：

1. **`assert-publishable.mjs` 第④条**：发布提交必须已并入 `origin/main`。此前三道断言只要求「HEAD 被发布 tag 指向」，看不见「tag 打在一个没合并的提交上」这种漂移。
2. **CHANGELOG 与 `doc-version` 两道闸**：发布前核对 CHANGELOG 有对应版本段、`docs/` 的 `doc-version` 标记与 SDK 版本一致。
3. **`prepublishOnly` 补回发布守卫**，并加断言盯住「守卫到底挂没挂上」。

## 五、其他修复与改进

- **学生作业附件可预览**：待提交与已归档提交都能看内容，docx/pptx/xlsx/zip 由内置渲染兜底，并留出**文件级预览扩展插槽**给插件接管冷门格式。
- **Node 运行时守卫**：安装期硬闸 + 启动期可读兜底，支持范围收敛到实测过的 **20.x / 22.x / 24.x**。
- **无障碍门禁改为「带数据扫描」**：堵住整类「内容一出现就违规」的漏检；同时修掉课表课程卡与课表页的三处 WCAG 对比度不达标。
- **客户端错误上报不再误报**：主动取消的请求（切页/卸载时的 abort）不再被记成「网络请求失败」并转发给教师。
- **课堂体验**：机房管理刷新后不再跳回第一台机房；组件属性编辑器保存成功/失败就地提示；白板画布装不下时由容器出滚动条；开发环境「同页两份 React」导致白板挂载崩溃的问题修复。
- **代码清理**：清点 `src/features/` 下 12 个「有实现、有单测、但生产零引用」的孤儿模块，按风险分三组处置（删除 4 个 / 标 `@experimental` 4 个 / 留待产品决策 4 个）。

## 六、验证与升级说明

1. **验证**：`pnpm lint`（`tsc --noEmit`）0 error；ESLint 告警预算 **6242 / 上限 6243**；格式棘轮不合规 **0** 个；`audit-tools/run.sh` → `drift_count=0`（含新增的扩展点覆盖门禁与文档内链 223 条失效 0）；版本一致性门禁 7 例通过。
2. **发布形态自检**：`scripts/publish.sh --dry-run` 通过 —— `version=0.7.5` / `sdk=3.7.4`（精确 pin）/ `preloadInFiles=true` / `preloadExists=true` / `guardInFiles=true` / `guardExists=true`；产物 **119 个文件**、6.1 MB。
3. **迁移**：本版本**不含新增迁移文件**（沿用 44 个 `.sql`）。
4. **行为变化（请留意）**：
   - **Node 版本收敛**：支持 20.x / 22.x / 24.x；不在范围内时**安装期即拒绝**（`better-sqlite3` 的原生模块 ABI 不兼容，混用会在启动第一句崩）。
   - **npm 上 3.7.1 不可用**：已标记弃用，请使用 3.7.4。
   - **发布行为**：任何直接 `npm publish` 都会被 `prepublishOnly` 拦下（依赖本地协议 / 版本不一致 / HEAD 未被打发布 tag / 提交未并入 main）。请走 `scripts/publish.sh`。
5. **插件作者**：本版本**未改动 SDK 的公开类型形状**；但新增了两条运行时约束 —— 题库题型与「课堂阶段门禁 / 课堂互动提供者」现在会随插件停用**自动回收**。若你此前依赖「停用后注册项仍在」的行为（不符合语义），请改为在 `deactivate()` 中显式保留所需的持久状态。
