# Release Notes v0.7.4

**发布日期**: 2026年10月25日

OpenLearn V2 **v0.7.4** 是平台的**发布链路加固版本（Release Pipeline Hardening）**。本版本不谈功能 —— 它修的是「发布这件事本身」的三处真实事故，以及一处让开发库被无障碍门禁长期污染的数据泄漏。

本版本的核心背景是一次**真实的发布事故**：2026-10-25 15:22，npm 上的 `openlearn-next@0.7.3` 被一次**绕过 `scripts/publish.sh` 的直接 `npm publish`** 发布出去，其产物把 pnpm 的本地依赖协议 `"@openlearn/plugin-sdk": "workspace:*"` 原样带进了发布包。消费者安装该版本必然报 `EUNSUPPORTEDPROTOCOL`（`Unsupported URL Type "workspace:"`）—— **整个版本装不上**；同时该产物的 `gitHead` 指向分支 HEAD（`cf9be45`）而不是发布 tag（`7220214`），npm 上的版本与仓库 tag 失去对应。npm 的版本一旦发布即不可变，且**网页端没有"撤回单个版本"的入口**（官方文档：该操作仅 CLI 可用），而 CLI 侧又被 npm 2026-07-31 起的新策略（"绕过 2FA 的 granular access token 不得用于包管理动作"）挡住 —— 于是该版本无法原地修复。

**处置结果**：0.7.3 已在 npm 上标记**弃用**（附明确原因说明），`latest` 标签临时回退到最后一个可用版本 0.6.0 以**立即保护消费者**，并由本版本 0.7.4 接棒 —— 0.7.4 的产物严格来自 `v0.7.4` tag，且发布前多了一道 npm 自己会执行的前置守卫。

> **v0.7.3 → v0.7.4 共 4 个提交**，跨 4 个文件（不含 v0.7.3 段已记录的 3 条发布工具链修复）。

## 一、发布前守卫：直接 `npm publish` 会被当场拦下

这是本次事故的**直接防线**，把「发布必须满足的前提」从「只活在某个脚本里」变成「npm 自己也会检查」。

1. **新增 `scripts/assert-publishable.mjs`**，挂在根 `package.json` 的 `prepublishOnly`，在 npm 打包前执行三道断言：
   - ① **依赖里不得出现本地协议**（`workspace:` / `link:` / `file:`，覆盖 `dependencies` / `optionalDependencies` / `peerDependencies`）—— 这类 spec 消费者无法解析（EUNSUPPORTEDPROTOCOL）；
   - ② **`packages/core/version.ts` 的 `FALLBACK_VERSION` 必须等于 `package.json` 的 `version`**；
   - ③ **当前 HEAD 必须正好被 `v<version>` 指向** —— 发布必须发生在打了发布 tag 的提交上，npm 上的版本与仓库 tag 才谈得上对应。
2. **为什么不再依赖 `publish.sh`**：`publish.sh` 里那条把 SDK 依赖改写成精确 pin（`3.7.0`）的 `sed` **只在脚本流程内生效**。绕开脚本，就绕开了它 —— npm 不会替发布者改写 `workspace:`。守卫挂在 npm 生命周期上，**任何**发布路径都会经过它。
3. **验证（实测退出码）**：
   - SDK 仍是 `workspace:*` 且未打 tag → **退出码 1**，逐条打印「本地协议」与「HEAD 未被 tag 指向」两条原因；
   - 改写成精确 pin `3.7.0`、仍未打 tag → **退出码 1**，只剩「HEAD 未被 tag 指向」一条；
   - 改写 pin 且 HEAD 已被 `v0.7.4` 指向 → **退出码 0** 放行。
   - **反向验证**：三种状态分别命中三条断言中的对应条，不是无条件放行 —— 护栏能力未被削弱。
4. **影响面**：`scripts/` 不在 `package.json` 的 `files` 清单内，不进入发布包本体；根 `package.json` 多一条生命周期脚本声明，不影响消费者安装（registry tarball 安装不执行 `prepublishOnly`）。

## 二、版本占用门禁改判「tag 是否与本次发布的提交同源」

1. **问题**：v0.7.2 引入的版本占用门禁写成「git tag `v<version>` 存在即拒绝发布」，但仓库既定的发布顺序恰恰是「提交（含版本提升）→ 打 tag → 执行 `publish.sh`」—— **tag 一打就再也发不出去**，门禁与流程自相矛盾。
2. **根因**：门禁想防的是「同一个版本号指向两批不同的代码」，却用「tag 存在」当代理判据；真正要判的是 **tag 指向的提交是否就是本次发布的提交**。
3. **改法**：判据改为三态 —— ① tag 不存在 → 放行（允许先发后补 tag）；② tag 存在且指向本次提交 → 放行（正是想要的状态）；③ tag 存在但指向别的提交 → 拒绝（并指名两个 commit）。npm 侧判据不变（已发布即拒绝，不可覆盖）。
4. **验证**：四组判据逐一实测退出码 —— tag 同源 → 0；tag 指向别的提交 → 1；无 tag → 0；npm 上已发布 → 1。

## 三、棘轮门禁不再让 npx 静默换版本

1. **问题**：格式棘轮与 ESLint 告警预算都用 `npx prettier` / `npx eslint` 调用工具，而 npx 在本地找不到对应包时会**联网拉一个最新版**—— 门禁的判定结果取决于「当时装的是哪个版本」。实测：仓库锁定 prettier 3.9.4，某次在缺 `node_modules` 的 worktree 里 npx 拉到 3.9.10，同一份 `README.md` 被判「不合规」，用锁定版本复判则完全合规（一度看着像真实回归，实为版本漂移假阳性）。
2. **为什么致命**：对**棘轮**门禁而言，格式判定会随环境漂移（基线失去意义）；ESLint 那边更糟 —— 新版 eslint 往往带来新规则，告警数只涨不跌。
3. **改法**：两个脚本都显式解析仓库内的工具入口（`node_modules/prettier/bin/prettier.cjs`、`node_modules/eslint/bin/eslint.js`）；找不到就**明确报错并提示 `pnpm install`**，而不是悄悄换一个版本去跑。
4. **验证**：缺 `node_modules` → 明确报错、退出码 1；装上锁定版本 → 格式不合规 0 个、ESLint 6243 = 基线 6243、error 0；**护栏能力未被削弱** —— 故意弄脏 `packages/core/version.ts` 仍报红（退出码 1），还原后恢复 0。

## 四、无障碍门禁不再往开发库里堆空白课节 / 空班级

1. **现象（实测）**：开发库里堆了 **5 个完全空白的课节**（`whiteboard_elements = 0`、`timeline = null`、无排课）+ **10 个空班级**，全部叫 `A11Y 学生端课节 …` / `A11Y 班级 …` / `A11Y 测评班 …`。按前缀统计可见铁证：`A11Y ` 前缀残留 5+10，而 `A11Y2` 前缀残留 **0**。
2. **根因**：门禁三个子用例分别建 `A11Y 学生端课节` / `A11Y 测评班` / `A11Y2 仪表盘课节`，而 `test.afterAll` 的清理条件写的是 `startsWith('A11Y2 ')` —— 只命中第三块，前两块每次运行都永久留下 1 个空课节 + 2 个空班级。兜底脚本 `scripts/cleanup-test-data.mjs` 当时也只认 `E2E ` / `canary` / `金丝雀`，同样不认 `A11Y`。
3. **改法**：
   - `e2e/a11y-gate.spec.ts`：把前缀抽成 `TEST_TAG` / `LESSON_PREFIX` / `CLASS_PREFIX` / `STUDENT_PREFIX` 四个常量，**创建与清理全从同一组常量派生**，不可能再漂移；
   - `scripts/cleanup-test-data.mjs`：把前缀抽成 `TEST_NAME_PREFIXES` / `TEST_NAME_MARKERS` 常量并补上 `A11Y `；把 `segment_visits` / `segment_gate_overrides` 纳入课节级联（原先留下 19 条孤儿访问记录）；测试学生匹配从只认 `STU_%-%` 扩展为枚举 15 个 spec tag。刻意**不**退化成「`STU_` 开头就删」—— 那会误伤人工建的普通测试学生。
   - **合并后补漏**：清理脚本原本**完全没有 `assessments`** —— 测评不挂在课节上，既不会被课节级联带走、也不在清理范围内，而门禁的「学生端我的测评」用例恰恰会建 `A11Y 测评 <suffix>`。实测开发库因此残留 **13 份 A11Y 测评**。现补上测评清理（含 `assessment_items` / `assessment_assignments` 子表级联）。
4. **验证**：修复后跑一次门禁 → 课节/班级/学生残留均为 **0**；在真库的**在线备份副本**上执行清理 → 课节 3→0、班级 6→0、测评 13→0、`assessment_items` 26→0，而 `test` 与 `[演示]` 课节、2 个演示班级、12 个学生、白板元素**分毫未动**（先在副本验证，确认无误后才作用于真库，并另留可回滚备份）。

## 五、验证与升级说明

1. **验证**：`pnpm lint`（`tsc --noEmit`）0 error；ESLint 告警预算 6243 = 基线 6243；格式基线棘轮不合规 **0** 个；源码编码与 i18n 检查通过；版本一致性门禁 7 例通过（0.7.4）。
2. **发布形态自检（消费者视角全链路实测）**：发布清单核对四项全过 —— `version=0.7.4` / `sdk=3.7.0`（精确 pin）/ `preloadInFiles=true` / `preloadExists=true`；产物 **115 个文件**；按 `files` 清单还原包并模拟真实消费（新建空项目 `npm install <tarball>` → 启动）→ `[Platform] Ready`、`GET /` 返回 **HTTP 200**。
3. **迁移**：本版本**不含新增迁移文件**（沿用 v0.7.2 的 44 个 `.sql` 与 v0.7.3 的 `migrations/schema-golden.json`）。
4. **行为变化（请留意）**：
   - **npm 上 0.7.3 不可用**：该版本已标记弃用，且因 `workspace:` 依赖协议无法安装。若你的锁文件或 CI 固定了 `openlearn-next@0.7.3`，请升到 0.7.4；在此之前可临时用 0.6.0。
   - **发布行为变化**：今后**任何**直接 `npm publish` 都会被 `prepublishOnly` 拦下（依赖本地协议 / 版本不一致 / HEAD 未被打发布 tag）。请走 `scripts/publish.sh`。
