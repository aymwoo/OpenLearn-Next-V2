# Release Notes v0.3.3

**发布日期**: 2026年9月6日

OpenLearn V2 **v0.3.3** 是针对生产独立部署与 CLI 运行模式（`npx openlearn-next@latest`）下 **Socket.IO 握手与跨域（CORS）通信链路的稳定性修复补丁**。本版本解决了未显式配置 `ALLOWED_ORIGINS` 时，生产环境 CORS 白名单误将本地同源请求拦截导致 HTTP 400 Bad Request 的问题，实现智能同源识别与本地回环自动放行。

---

## 主要更新

### 1. Socket.IO & Express CORS Same-Origin 智能放行机制
- **根因消除**：此前的安全收紧策略在生产环境下（`process.env.NODE_ENV === 'production'`）当未指定 `ALLOWED_ORIGINS` 时默认为空列表 `[]`，并在检查回调中抛出 `new Error('CORS not allowed')`。由于现代浏览器在发起 Socket.IO 轮询与 POST 连接时均会携带当前页面的 `Origin` 头部（如 `http://localhost:9000`），该检查将自身同源请求误拦截，底层 Engine.IO 接收到异常抛出后直接响应 `HTTP 400 Bad Request {"code": 3, "message": "Bad request"}`。
- **智能同源判定**：抽象并引入统一的 `isOriginAllowed(origin, hostHeader)` 判定算法：
  - **显式配置优先**：支持 `ALLOWED_ORIGINS` 指定的具体域名及通配符 `*`；
  - **Same-Origin 同源放行**：比较请求的 `Origin` host 与 HTTP `Host` 头部，若完全一致则自动安全放行；
  - **本地回环安全放行**：对 `localhost`、`127.0.0.1`、`[::1]`、`0.0.0.0` 来源自动予以放行；
  - **跨域安全防御**：对于未授权的第三方外部域名（如 `evil.com`），CORS 响应中安全剔除 `Access-Control-Allow-Origin` 头部，由浏览器标准阻止恶意跨域访问，且严禁通过 `callback(new Error(...))` 引发底层服务 400 崩溃。

### 2. 断线重连与 Session ID 恢复稳定性
- 解决了服务重启后浏览器持有旧 Session ID（sid）触发会话重新协商时，因 CORS 阻断陷入无法重新 handshake 的死循环。
