# Release Notes v0.7.6

**发布日期**: 2026年10月27日

OpenLearn V2 **v0.7.6** 是 v0.7.5 之后的**补丁版本**：修掉一个插件配置热更新缺陷，补上一道发布 / 文档门禁的漏洞，并把带日期的审计快照从正式文档区归档。

> **v0.7.5 → v0.7.6 共 8 个提交、64 个文件（+941 / −1,084）**。不含新增数据库迁移（沿用 44 个 `.sql`），不含 SDK 变更（`@openlearn/plugin-sdk` 保持 3.7.4，`@openlearn/plugin-test-kit` 保持 3.3.3）。

## 一、插件配置真正热更新（#338）

### 1.1 现象

管理端在插件详情页改配置、保存成功，但**运行中的插件读到的还是旧值**，`onChange` 回调也不触发 —— 必须重启宿主才生效。`docs/architecture/configuration.md` 此前把这条如实记为「跨实例的变更广播未实现」的已知限制。

### 1.2 根因

`ConfigService` 的缓存与监听器都是**实例私有**的：

- 插件的 `ctx.config` 是 `context-builder.ts` 在激活时创建的长生命周期实例；
- 管理端读写走 `core.ts` 的 `getPluginConfig` / `setPluginConfig`，每次都 **new 一个临时实例** —— 写入只落库，插件的实例既不会失效自己的缓存，也收不到通知。

### 1.3 改法

同一 `db` 对象 + `manifest.id` 的所有实例现在共享一份缓存与实例表（模块级 `WeakMap<db, Map<manifestId, { values, instances }>>`）：

- 任一实例 `setSync()` 写入后，**所有活跃实例立即读到新值**；
- 写入**广播给所有活跃实例**，运行中插件的 `onChange` 被触发，`oldValue` 取共享缓存中的上一个值；
- 实例用 `WeakRef` 登记 + `FinalizationRegistry` 清理：插件卸载后不会把事件送进已废弃的上下文，也不阻止其实例被回收；
- `loadFromDB()` 改为**以 DB 为准重建**共享缓存（此前只合并不清空），重装 / 恢复备份 / 换库后不残留旧值。

`IConfigService` 的公开签名不变，插件侧无需改动。

### 1.4 已知边界（保持不变）

`onChange` 仍然**不带作用域参数** —— 班级层与平台层的写入在回调里长得一样；需要区分来源时仍需自行记录。`oldValue` 是共享缓存里的上一个值，不是数据库里的历史值。

## 二、发布门禁补洞：CHANGELOG 的版本注记（#336）

`scripts/check-doc-version.mjs` 此前只扫 `docs/**` 里的 `<!-- doc-version: sdk=X.Y.Z -->` 标记。根 `CHANGELOG.md` 顶部那句**给人读**的版本注记：

```
> `@openlearn/plugin-sdk` (currently **3.7.4**) and `@openlearn/plugin-test-kit` (currently **3.3.3**).
```

不在任何门禁覆盖内 —— v0.7.5 发版准备时把这句改错，**门禁、CI、发版三处都不报**。

现在脚本按包名匹配 `currently **X.Y.Z**` 并与对应 `package.json` 的 version 比对；注记**缺失**同样失败（`changelog-note-missing`）。校验口径从 26 篇文档扩展到 **26 篇文档 + 2 条注记 = 28**。

## 四、验证与升级说明

1. **验证**：`pnpm lint`（`tsc --noEmit`）0 error；`packages/core/plugin-host` 全量 387 例通过（其中配置服务 30 例，新增 10 例跨实例用例）；`packages/core/worker-runtime` 子进程隔离集成测试通过；`audit-tools/run.sh` → `drift_count=0`、失效文档链接 0。PR #338 的 CI 全绿（typecheck-and-test、coverage、E2E、格式与文档门禁）。
2. **迁移**：本版本**不含新增迁移文件**（沿用 44 个 `.sql`）。
3. **行为变化（请留意）**：
   - 管理端保存插件配置后，运行中插件**立即**读到新值并收到 `onChange`。此前依赖「重启才生效」的插件不需要改代码；若某个插件把「配置不会变」当作不变量缓存了派生状态，应改为响应 `onChange`。
   - 配置缓存现在按 `db` + `manifest.id` 共享；不同插件之间仍然完全隔离。
4. **插件作者**：**SDK 公开类型无变化**，`ctx.config` 的方法签名与语义不变。
