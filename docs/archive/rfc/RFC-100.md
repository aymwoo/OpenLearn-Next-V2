# RFC-100: Product Extension Architecture Specification (产品扩展架构规范)

## 1. Extension Point Specification (扩展点接口规范)

所有产品能力与模块在暴露扩展之前，**必须**首先声明对应的 `ExtensionPoint`。

```typescript
export type ExtensionPointCategory =
  | 'UI'
  | 'Capability'
  | 'Event'
  | 'Workspace'
  | 'Pipeline';

export interface ExtensionPoint<T = unknown> {
  readonly id: string;
  readonly name: string;
  readonly category: ExtensionPointCategory;
  readonly description?: string;
  readonly schema?: Record<string, unknown>;
  validate?(extension: T): boolean;
}
```

---

## 2. Unified UI Slots (统一 UI 插槽图谱)

前端 UI 扩展**必须**归属并挂载至以下 9 大标准 `UISlot` 节点：

| UI Slot 名称 | 说明 | 挂载位置 |
|---|---|---|
| `Toolbar` | 主/子工具栏 | 顶部/工具列 |
| `Sidebar` | 侧边栏抽屉面板 | 屏幕左右侧 |
| `Inspector` | 属性检查与控制面板 | 屏幕右侧 |
| `CanvasOverlay` | 画布透明浮层 | 2D/3D 画布上方 |
| `ContextMenu` | 鼠标右键上下文菜单 | 鼠标焦点位置 |
| `StatusBar` | 底部状态栏 | 屏幕最下方 |
| `WorkspacePanel` | 工作区主面板 | 中央工作区 |
| `Dialog` | 模态对话框 | 居中浮层 |
| `FloatingPanel` | 自由浮动面板 | 任意坐标位置 |

```typescript
export type UISlotType =
  | 'Toolbar'
  | 'Sidebar'
  | 'Inspector'
  | 'CanvasOverlay'
  | 'ContextMenu'
  | 'StatusBar'
  | 'WorkspacePanel'
  | 'Dialog'
  | 'FloatingPanel';
```

## 3. Capability Runtime Isolation (能力代理规范)

- **禁令**: 任何扩展或外部模块**绝对禁止直接调用内部业务 Class 或私有函数**。
- **强制约束**: 所有能力必须通过 `CapabilityRuntime` 统一暴露与解算。

```typescript
// ✅ 正确：通过 CapabilityRuntime 访问能力
const chatCap = capabilityRuntime.resolveCapability('capability_chat');
await chatCap.chat("Hello");

// ❌ 禁用：直接创建或导入内部 Service
// const service = new InternalAIService(); 
```

---

## 4. Unified Event Naming (统一事件命名规范)

事件类型使用 **过去时形态 (Past Tense)** 的动名词组合命名：

- `LessonStarted`: 课堂已开始
- `LessonEnded`: 课堂已结束
- `WhiteboardChanged`: 白板画布已变更
- `StudentJoined`: 学生已加入
- `PluginLoaded`: 插件已加载
- `AICompleted`: AI 任务已完成

---

## 5. Workspace Widget Principle (工作区 Widget 封装原则)

所有交付的产品功能在视图层最终均包装为标准的 **`WorkspaceWidget`**，以便在工作区面板中弹性布局、拖拽解耦与显隐控制。

---

## 6. Plugin-First Principle (插件优先开发原则)

任何新功能或核心业务特性在正式编码前，**必须先设计并声明其 Extension Point**，确保核心逻辑天然可被第三方插件拦截、增强或重置。
